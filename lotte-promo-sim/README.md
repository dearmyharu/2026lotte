# 홈쇼핑 프로모션 시뮬레이터 (LOTTE AX Challenge 2026 · 과제 3)

> 어떤 혜택을, 얼마나, 언제 걸어야 **진짜 이익**이 늘어나는가.

카드 청구할인 · 사은품 · 무이자 할부 · 적립금 · 방송 중 추가혜택의 **288개 조합**을 시뮬레이션하고,
홈쇼핑·협력사·카드사의 비용 분담과 '당겨쓰기'까지 반영해 최적 조합을 추천하는 AI 에이전트입니다.

## 왜 필요한가
- TV홈쇼핑은 방송매출의 약 70%가 송출수수료로 나가는, 마진이 얇은 구조입니다. 효과 없는 혜택 1원이 곧 손실입니다.
- 현업에서 흔한 "혜택 건 방송 vs 안 건 방송" 비교는 **잘 팔릴 방송에 혜택을 몰아준 효과**까지 혜택 덕으로 착각합니다.
- 혜택을 키우면 주문은 늘지만, 판촉비와 다음 주 수요를 당겨온 손실 때문에 **이익은 줄 수 있습니다.**

## 핵심 기능
| 탭 | 내용 |
|---|---|
| 🤖 AI 에이전트 | MD가 자연어로 질문 → 에이전트가 시뮬레이터 도구를 골라 실행 → 근거와 함께 추천 |
| 🎯 최적안 찾기 | 목표(홈쇼핑 이익 / 공동 이익), 협력사 하한, 판촉비 상한, 보수 모드 조건으로 288개 조합 탐색 |
| 🧪 직접 시뮬레이션 | 두 조합 비교, 90% 신뢰구간, 주체별 판촉비 |
| ⏱️ 추가혜택 타이밍 | 방송 중 추가혜택을 몇 분에 꺼낼지 (분당 주문 곡선) |
| 📊 혜택 반응표 | 카테고리별로 혜택 하나가 주문을 몇 % 늘리는지 |
| ✅ 검증 | 정답 대비 정확도, 단순 비교 대비 개선 폭, 의사결정 품질 |

## 반영한 업계 현황과 규제
| 현황 | 시뮬레이터에 반영한 방식 |
|---|---|
| 송출수수료가 방송매출의 73.4% (롯데홈쇼핑 69.6%) | 시간대별 방송 고정비로 반영, 혜택은 '증분 이익'으로만 판단 |
| 대규모유통업법 제11조: 협력사 판촉비 분담 50% 이하 (2021년 사은품 비용 전가로 TV홈쇼핑 6개사 제재) | 기본 분담을 법 준수 구조로 설정, 50% 초과 조합은 추천에서 자동 제외 (협력사 자발적 행사는 예외 토글) |
| 납품업체 실질수수료율 27.7% (업태 중 유일하게 상승) | 협력사 손익을 별도 계산해 '협력사가 받아들일 수 있는가'를 제약 조건으로 |
| 구매자의 약 69%가 방송을 보고 모바일로 결제 | 방송 후 7일 앱 주문을 따로 예측해 당겨쓰기 반영 |
| 2026년 5월 상생·활력 제고 방안 (중기 편성 완화, 정액방송 확대 검토) | 분담·수수료 구조를 바꾸면 최적안을 즉시 재계산 (향후 정액/정률 방송 구분 추가 예정) |

## 검증 결과 (가상 데이터 · 정답을 심어둔 채점 방식)
실제 데이터가 없으므로, **혜택의 진짜 효과를 미리 정해둔 가상 세계**(`sim/truth.py`)에서 데이터를 만들고,
모델이 그 정답을 보지 않고 얼마나 맞히는지 채점했습니다.

| 항목 | 결과 |
|---|---|
| 처음 보는 방송 1,200회 주문 예측 | R² 0.89, 평균 오차 18.8% |
| 혜택 효과 추정 오차 | **3.6%p** (단순 비교 방식은 36.7%p) |
| 추천 조합의 이익 | 정답을 아는 최적안 대비 **65%** 확보, 이익 감소 방송 3% |
| 혜택을 최대로 다 거는 관행 | 최적안 이익의 **약 4배 손실** (최적안 대비 -406%) |
| 협력사 보호 | 일반 모드: 협력사 이익 평균 +4.0%, 조건 준수 97% / 보수 모드: 준수 100%, 이익 확보 45% |

`python -m sim.validate` 로 재현할 수 있습니다. 결과는 `artifacts/validation.json`.

**한계**: 가상 데이터 기준입니다. 실제 데이터에는 관측되지 않는 요인(경쟁사 동시간대 방송, 날씨 등)이 있어,
일부 방송의 혜택을 무작위로 편성하는 **탐색 편성**으로 지속 검증·재학습하는 운영을 전제로 합니다.

## 구조
```
app.py                  Streamlit 앱 (6개 탭)
sim/config.py           카테고리·시간대·혜택 선택지·비용 분담 가정값
sim/truth.py            정답 세계 (데이터 생성·채점에만 사용, 모델은 보지 않음)
sim/data_gen.py         가상 방송 6,000회 생성 (MD 편향 = 교란 포함, 10% 탐색 편성)
sim/model.py            반응 예측 모델: GBM + 카테고리별 포아송 GLM 앙상블, 부트스트랩 20개
sim/economics.py        3자 비용 분담 손익 계산, 당겨쓰기 반영, 제약 하 최적화
sim/minute_profile.py   분당 주문 곡선 (추가혜택 비용·타이밍)
sim/validate.py         3단계 검증 (예측 / 효과 추정 / 의사결정)
sim/tools.py            에이전트 도구 6개 + OpenAI 함수 스키마
sim/agent.py            OpenAI 함수 호출 에이전트 + 숫자 근거 검사
```

### 모델 설계 요약
- **증분 효과** = 같은 방송 조건에서 [혜택 있음 예측] − [혜택 없음 예측]. 시간대·인기도·호스트를 함께 학습해 교란을 걸러냄
- **단조성 제약**: 혜택을 키웠는데 주문이 줄어드는 비상식적 예측을 구조적으로 차단
- **앙상블**: GBM(비선형 패턴) × GLM(해석 가능한 혜택 계수)의 기하평균. 검증에서 단독보다 정확
- **불확실성**: 부트스트랩 20개 모델로 90% 구간과 '이익 증가 확률' 제시
- **당겨쓰기**: 방송 후 7일 앱 주문을 별도 모델로 예측해, 미래 수요를 당겨온 만큼 이익에서 차감

### 에이전트 안정성 장치
1. 숫자는 도구(시뮬레이터)에서만: LLM은 질문 해석과 설명만 담당
2. **근거 검사**: 답변 속 숫자가 도구 결과에 실제로 있는지 자동 검사, 없으면 경고 표시
3. 입력 검증: 카테고리·시간대·혜택 값은 정해진 선택지만 허용, 오류 시 LLM이 스스로 수정
4. 도구 호출 최대 6회

## 실행
```bash
pip install -r requirements.txt
python -m sim.data_gen      # 데이터 생성 (이미 data/ 에 있음)
python -m sim.validate      # 검증 + 모델 저장 (약 2분)
streamlit run app.py
```
에이전트 탭은 OpenAI API 키가 필요합니다 (`.streamlit/secrets.toml` 또는 화면에서 입력).
모델은 환경변수 `OPENAI_MODEL`로 바꿀 수 있습니다 (기본 `gpt-4.1-mini`).
